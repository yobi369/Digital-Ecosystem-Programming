# Digital Ecosystem Programming Lab

An interactive artificial-life and ecology programming laboratory. Build and observe a virtual ecosystem with organisms, heritable genomes, resource dynamics, trophic interactions, environmental disturbances, population telemetry, and educational experiments.

> **Scientific status:** this is an exploratory educational simulation, not a validated ecological model. Its outputs are generated by software rules and should not be presented as empirical predictions or evidence about real ecosystems. See [scientific model limitations](docs/SCIENCE_AND_VALIDATION.md).

## What the application currently contains

- **World simulation:** a 2D environment with plants, organisms, food resources, and environmental settings.
- **Organism behaviours:** movement, sensing, feeding, predation, reproduction, mutation, ageing, and death.
- **Species and genomes:** preset organism types and a gene laboratory for custom genomes.
- **Environmental interventions:** disasters and changes to environmental conditions.
- **Telemetry:** population time series, trait summaries, trophic views, and lineage visualisation.
- **Persistence and export:** world save/load and telemetry export interfaces.
- **Learning tools:** guided scenarios, quests, an organism inspector, and a code lab.

Capabilities listed here describe the current codebase; they do not imply scientific validation or production-grade data persistence.

## Technology

- React 19 and TypeScript
- Vite 6
- Tailwind CSS 4
- Canvas-based rendering
- Recharts for telemetry visualisation
- Bun lockfile and package management

## Requirements

- Bun (recommended; the repository includes `bun.lock`)
- A current LTS Node.js runtime compatible with the installed Vite toolchain

## Run locally

```bash
bun install --frozen-lockfile
bun run dev
```

Open the local URL printed by Vite (the dev server is configured for port 3000).

## Quality checks

```bash
bun run lint
bun run build
```

The current automated gates perform TypeScript compilation and a production Vite build. They are not a substitute for behavioural, scientific, accessibility, or browser-based acceptance tests. The project must not claim a test suite or coverage percentage until those checks exist and run in CI.

## Configuration and secrets

The current client is a browser application. Never place private API keys, service credentials, or privileged tokens in Vite-exposed variables or committed files. Variables prefixed with `VITE_` are bundled for browser access and must be treated as public.

The repository includes an environment example for the AI Studio hosting workflow. Review it before using a different host; do not assume AI Studio-injected values exist in Vercel, Netlify, or a local deployment.

## Deployment

The application builds to `dist/`:

```bash
bun run build
bun run preview
```

For Vercel, import this repository and use:
- Framework preset: Vite
- Install command: `bun install --frozen-lockfile`
- Build command: `bun run build`
- Output directory: `dist`

The project currently has no application server or database. Browser-local state and in-memory simulation state are not a multi-user persistence service. Do not use this build to store sensitive research or learner records.

## Scientific use

For classroom exploration, record the exact configuration, simulation duration, initial conditions, randomisation procedure, and software revision for every experiment. Do not infer real-world population trajectories from the current simulation. The scientific validation roadmap in [docs/SCIENCE_AND_VALIDATION.md](docs/SCIENCE_AND_VALIDATION.md) defines the work required before stronger claims are appropriate.
